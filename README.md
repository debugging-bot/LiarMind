# LiarMind (라이어마인드)

캐치마인드 + 라이어 게임을 결합한 Java 소켓 네트워크 게임 (네트워크프로그래밍 텀프로젝트)

- 서버: `LiarMindServer.java` (수업 예제 `JavaChatServer.java` 확장)
- 클라이언트: `LiarMindClientMain.java`, `LiarMindClientView.java` (수업 예제 확장, 팀원 B)
- 서버 테스트용: `LiarMindTestClient.java` (콘솔에서 명령어를 직접 입력)

## 실행 방법

1. `LiarMindServer` 실행 → 포트 확인(기본 30000) → `Server Start`
2. 클라이언트 여러 개 실행 → 닉네임, 서버 IP(같은 컴퓨터는 127.0.0.1), 포트 입력 후 접속

## 메시지 프로토콜

- 모든 메시지는 `DataOutputStream.writeUTF()` / `DataInputStream.readUTF()`로 문자열 한 개씩 주고받는다.
- 형식: `/명령어 내용` (명령어와 내용은 공백 하나로 구분, 내용 안에는 공백이 있어도 됨)
- 닉네임에는 공백과 쉼표를 쓸 수 없다 (최대 10자).

### 1주차 (구현 완료)

| 메시지 | 방향 | 설명 |
| --- | --- | --- |
| `/login 닉네임` | 클라이언트 → 서버 | 접속 직후 반드시 첫 메시지로 보낸다 |
| `/loginok 닉네임` | 서버 → 본인 | 접속 성공 |
| `/reject 이유` | 서버 → 본인 | 접속 거부 후 서버가 연결을 끊는다. 이유: `empty` 빈 이름, `invalid` 공백·쉼표 포함, `toolong` 10자 초과, `duplicate` 중복 닉네임, `full` 8명 초과, `started` 게임 진행 중, `login_required` 첫 메시지가 /login이 아님 |
| `/users 이름1,이름2,...` | 서버 → 전체 | 접속자 목록. 순서 = 프로필 칸 순서, **첫 번째 이름이 방장**. 입장·퇴장 때마다 전송 |
| `/system 내용` | 서버 → 전체/본인 | 안내 문구 (입장, 퇴장 등). 채팅창에 표시 |
| `/chat 내용` | 클라이언트 → 서버 | 채팅 보내기 |
| `/chat 보낸이름 내용` | 서버 → 전체 | 채팅 받기 (보낸 사람 본인에게도 돌아옴) |
| `/exit` | 클라이언트 → 서버 | 정상 퇴장 (창을 그냥 닫아도 서버가 퇴장 처리함) |

### 2주차 (구현 완료)

| 메시지 | 방향 | 설명 |
| --- | --- | --- |
| `/draw x1 y1 x2 y2 색RGB 굵기` | 그리는 사람 → 서버 → 전체 | 선분 하나. 서버가 정수 6개·굵기 1~50인지 검사한 뒤 보낸 사람 포함 모두에게 전달. 게임 중에는 지금 차례인 사람의 것만 전달 |
| `/clear` | 클라이언트 → 서버 → 전체 | 대기실: 그림판 전체 지우기. 게임 중에는 4주차부터 `/clear 이름`으로 바뀜 (아래 4주차 참고) |

### 3주차 (구현 완료)

| 메시지 | 방향 | 설명 |
| --- | --- | --- |
| `/start 바퀴수` | 방장 → 서버 | 게임 시작. 바퀴수 1~3, 3명 이상. 시작하면 새 입장은 `/reject started` |
| `/word 카테고리 제시어` | 서버 → 개별 | 제시어 전달. 라이어는 `/word 카테고리 ?` (카테고리만) |
| `/turn 이름 바퀴 제한시간` | 서버 → 전체 | 그릴 차례 (예: `/turn 민지 1 20`). 제한시간(초)이 지나면 서버가 자동으로 다음 차례로 넘김 |
| `/next` | 그리는 사람 → 서버 | 다음 차례로 |
| `/votestart` | 서버 → 전체 | 투표 시작 (30초). 4주차: 동점이면 `/votestart 이름1,이름2`로 후보를 붙여 다시 보냄 |
| `/vote 이름` | 참가자 → 서버 | 라이어라고 생각하는 사람에게 투표 (자기 자신 불가, 한 번만) |
| `/guessstart 이름` | 서버 → 전체 | 지목된 사람이 라이어일 때 정답 기회 (20초) |
| `/guess 단어` | 라이어 → 서버 | 제시어 맞히기 (띄어쓰기 무시) |
| `/result 승리팀 라이어 제시어` | 서버 → 전체 | 결과. 승리팀은 `LIAR`, `CITIZEN`, `CANCEL`(라이어 퇴장·인원 부족) |
| `/score 이름:점수,...` | 서버 → 전체 | 점수. 시민 승리 시 시민 +1, 라이어 승리 시 라이어 +2 |

- 게임 진행 안내(투표 현황, 투표 결과, 시간 초과 등)는 `/system`으로 보낸다.
- 제시어는 프로젝트 폴더의 `words.txt` (`카테고리,제시어` 한 줄에 하나, UTF-8)
- 아무도 투표하지 않으면 라이어 승리. 동점이면 4주차부터 동점자끼리 한 번 더 투표하고, 다시 동점이면 라이어 승리

### 4주차 (구현 완료: 서버)

| 메시지 | 방향 | 설명 |
| --- | --- | --- |
| `/ready` | 참가자 → 서버 | 준비 / 준비 취소 (누를 때마다 바뀜). 방장은 보내지 않음. 대기실에서만 |
| `/ready 이름1,이름2` | 서버 → 전체 | 지금 준비한 사람 목록 (아무도 없으면 `/ready`만 옴). 입장·퇴장, 준비 변경, 게임 시작 때마다 전송 |
| `/avatars 이름1:번호,이름2:번호` | 서버 → 전체 | 캐릭터 번호(1~8, 겹치지 않음). `/users` 바로 뒤에 같은 순서로 전송. 그림은 `images/avatar/avatar번호.png` |
| `/clear 이름` | 서버 → 전체 | 게임 중 그리는 사람이 `/clear`를 보내면 그 사람이 그린 선만 지움. 그리는 차례가 아닌 사람의 `/clear`는 `/system 지금은 그림을 지울 수 없습니다.`로 거절 |
| `/votestart 이름1,이름2` | 서버 → 전체 | 동점일 때 다시 투표. 투표 창에는 이 후보들만 표시. 후보가 아닌 사람에게 보낸 `/vote`는 서버가 거절 |

- 게임 시작 조건: 방장을 뺀 모든 사람이 준비해야 `/start`가 받아들여진다. 아니면 `/system 아직 준비하지 않은 사람이 있습니다: ...`
- 그리는 순서는 게임마다 무작위. 시작할 때 `/system 그리는 순서: 영희 → 민지 → 철수`로 알린다 (`/turn`은 그대로)
- 게임 중에는 `/clear`로 앞사람들의 그림까지 지워지지 않도록, 서버가 `/clear 이름`으로 바꿔 보낸다 (클라이언트 버튼: '내 그림 전체 지우기')
- 게임 메시지는 서버의 보내는 스레드 하나가 만들어진 순서대로 보낸다 (투표 현황 등이 뒤바뀌어 도착하지 않음)
